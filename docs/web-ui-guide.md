# Web UI Guide

The Paranoid web UI is available at `http://localhost:8000/app` when running via Docker or `uvicorn`. It provides a full browser-based interface for creating and reviewing threat models, managing projects, and collaborating with your team.

## Layout

The UI has two persistent chrome elements:

- **Sidebar** (264px): project selector, navigation links, user menu
- **Topbar** (54px): current page title, notifications bell, user avatar

Login (`#/login`) and Register (`#/register`) render without chrome.

---

## Dashboard (`#/`)

The home dashboard shows:

- **Stat cards**: total models, open threats (by severity), completed reviews
- **Open threat severity breakdown**: stacked bar across all active models
- **Assigned to you**: threats and models currently assigned to your account
- **Activity feed**: recent actions across the selected project

---

## Home — Model List (`#/home`)

Lists all threat models in the current project, most recent first.

Each **model card** shows: title, framework badge (STRIDE/MAESTRO), total threats, severity bar (critical/high/medium/low), status dot, and assignee avatars.

**Actions on the card:**
- Click to open Results
- **Compare** button — diff this model against another (see Model Diff)

**Status workflow:** `pending → in_progress → completed → in_review → approved → archived`

---

## New Model Wizard (`#/new`)

A step-by-step wizard for creating a threat model.

**Steps:**

1. **Title & Framework** — name your model; STRIDE, MAESTRO, or auto-detect
2. **Description** — paste or type your system description (or use a structured template)
3. **Diagram** — upload up to 5 architecture diagrams at once (PNG/JPG or `.mmd`/`.txt` Mermaid), each with an editable name and a kind chip; a rejected file never drops ones already accepted (optional)
4. **Code Source** — select a linked Git repository from the Sources page (optional)
5. **Dependencies** — optionally upload `package.json` (+ lockfile) for dependency capability analysis
6. **Assumptions** — list known assumptions about the system
7. **Iterations** — set the iteration count (1–15) for this run
8. **AI Components** — flag whether the system has AI/ML components (runs MAESTRO alongside STRIDE)
9. **Review & Run** — confirm everything and start the pipeline; progress shown via live SSE events

## Results (`#/models/:id`)

Shows the full threat model context and threat list after a run completes.

**Sections:**

- **Summary**: title, framework, provider/model used, run date, iteration count, duration
- **Run Summary**: per-step model (fast vs. main) and token usage, with a warning chip if fast routing fell back to the main model mid-run
- **Diagrams**: a single diagram renders directly; two or more show a tab strip (`role="tablist"`, arrow-key navigation). Each image loads lazily on first selection and is cached per tab
- **Dependencies**: a heatmap of packages × capability categories (network, filesystem, process, dynamic code, native addons, …), with expandable evidence and drift/skip reasons, shown when the run included a manifest
- **Context** (assets, flows, trust boundaries): click any item to expand; **Re-extract** button re-runs extraction without regenerating threats (reuses the model's stored diagrams; dependency manifests aren't persisted, so dependency analysis doesn't re-run here)
- **Threats**: filterable table by category, severity, and status; each threat can show ATT&CK/ATLAS technique chips and a CVSS badge alongside its DREAD score
- **Compare**: opens the Model Diff view

## Review (`#/models/:id/review`)

The human-in-the-loop approval interface.

**Per-threat card:**
- DREAD micro-chart (5 bars, colour-coded: critical/high/medium/low)
- DREAD score badge (e.g. `7.5 HIGH`) and, when scored, a CVSS v3.1 badge with inline vector editing
- ATT&CK/ATLAS technique chips (embedding-sourced matches shown as "suggested"), linking out to attack.mitre.org / atlas.mitre.org
- Category chip (Spoofing, Tampering, etc.) and, for dependency-engine threats, a "Dependency" chip with `pkg@ver · file:line`
- Target and likelihood
- Full description and mitigations
- **Approve** / **Reject** buttons
- Inline DREAD/CVSS score editing (no page reload)
- Assignee picker
- Comment thread (threaded, inline)

**Bulk actions:**
- Select multiple threats → approve or reject all selected
- Filter bar: category, status, severity

## Attack Tree (`#/models/:id/attack-tree`)

Visual attack tree generated by `--enrich` (requires Anthropic provider). Each node in the tree is a step in the attack path. Hover to see DREAD scores and Gherkin test cases.

---

## Model Diff (`#/models/:head_id/diff?base_id=...`)

Side-by-side comparison of two models using embedding similarity.

- **New threats**: in head but not base (above threshold)
- **Removed threats**: in base but not head
- **Unchanged threats**: matched by cosine similarity ≥ 0.85

Triggered via the **Compare** button on the Results page or model card.

## Sources (`#/sources`)

Manage Git repositories for code-grounded threat modeling.

**Add a source:**
1. Click **Add source**
2. Enter Git URL, optional name, optional branch/tag/SHA, optional PAT for private repos
3. Click **Add & clone** — live progress shown: `queued → cloning → indexing → ready`

Once `ready`, a source can be selected in the New Model Wizard.

**PAT storage**: encrypted at rest (Fernet, key derived from `CONFIG_SECRET`). The raw token is never shown after creation.

---

## Settings (`#/settings`)

Runtime configuration editor. Changes take effect immediately without restarting.

**Available settings:**
- Provider (Anthropic / OpenAI / Ollama / Bedrock)
- Model name
- Default iterations
- Fast model for the selected provider (each provider has its own fast-model field; empty disables routing for that provider)
- API keys (write-only; existing value shown as `***`)

If `CONFIG_SECRET` is set, the Settings page requires entering it before saving.

---

## Project Settings (`#/projects/:id/settings`)

Owner-only project configuration:

- Project name and description
- Per-project default provider, model, iterations, and temperature
- Danger zone: delete project

---

## Members (`#/projects/:id/members`)

Owner-only member management:

- View all members with their roles
- Invite a user by username or email (assigns a role: Viewer / Editor / Owner)
- Change an existing member's role
- Remove a member

---

## Admin — User Management (`#/admin/users`)

Instance admin only (`is_admin=true`):

- List all registered users
- Promote or demote admin status
- Deactivate accounts
